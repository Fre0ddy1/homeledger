# 借钱与金融开发约定

本轮按维护者2026-11-11确认的新模型实施，旧数据全部为测试数据，不维护按姓名汇总的历史借钱迁移。现有URL保留。设计见[批准方案](superpowers/specs/2026-11-10-borrowing-and-credit-design.md)，外部调用参数以[金融API参考](../skills/homeledger-bookkeeping/references/finance-api.md)为准。

## 资金与业务边界

- 账户及transactions是唯一资金事实。本金与转账无收支分类，不计收入支出；实际贷款/信用卡利息使用expense、手续费使用fee；原有interest仍是利息收入。
- `src/lib/borrowing.js`维护稳定的亲友借钱条目；明确debt_id关联，不按姓名合并。期初登记不造现金流，实际收还或关联已有流水才核销；软归档保留历史。
- `src/lib/finance/loans.js`维护合同及预计计划；`cards.js`维护账期、银行快照、差异、分期与实际费用；`payments.js`维护统一付款、资金分项、来源和分配。所有页面与开放API调用这些服务，不能手写资金SQL绕过保护。
- 本轮核销仅本位币、同币种；本位币汇率固定1，已有来源检查rate/amount_base_cents。钱按整数分计算，分币尾差进末期，模型不做算术。
- 合同及卡片关联账户不能通过普通账户编辑、删除、停用或调整余额破坏引用。期初卡余额进入指定账单，不重复计消费；放款流水受合同保护。

## 普通记账账户资格（2026-11-11）

- src/lib/account-policy.js 是 UI/API/定期/订阅/导入共用的资格规则。普通日常收支排除 loan/receivable/payable，credit 保留消费与退款。普通 transfer 两端及投资、借钱本金排除负债账户，实际还款使用统一入口。
- 受控金融服务以 createTransaction 第四个参数传入 channel:finance；不得从请求正文的 source/channel 推导权限。银行导入允许保留已经发生的金融转账和贷款入账，后续核销仍须公共金融服务。
- GET /api/open/accounts 新增 transaction_types 数组；不删账户或历史查询范围。表单只保留仍符合当前类型的账户选择，切换类型后无效选择清空；SSR 原生下拉与增强下拉一致。

## 自动抵扣与简化还款（2026-11-12）

默认信用卡付款保存allocation_mode=auto，显式allocations保存manual。card-allocation.reconcile只重建有效自动付款的关联；用户手工安排和银行金额快照保留。已出账负账单余额按最早到期抵扣，credit_applied_cents独立展示，不伪造付款。刷新、读取详情、流水变更及提醒调度共同推进出账/预还抵扣；保留零额账单ID以便查看原详情。所有重算必须位于事务中，不产生第二份资金流水。

贷款省略本金分项时先按原始请求做幂等检查，再带出最近未还期；实付与计划不符不得猜测利息。页面正常流程仅需确认已带出的金额，例外才展开分项/期次和已有来源。

## 不变量与操作

- operation_key是一次操作的身份；同key同请求复用结果，变参拒绝。更正付款使用新key，旧记录replaced_by保留追溯。来源只能由一份有效付款占用，撤销后可重新关联，恢复旧付款须再次检查占用及容量。
- 已有正确转账只补关联；已有银行扣款可确认替换为本金/费用，原始记录保留，不能多扣一份。撤销新生成资金组与解除已有转账关联有不同资金语义，界面及API回执必须说清楚。
- 核销不得超付款或期次/账单容量。草稿账单涉及手动安排且变更会超额时拒绝并回滚；自动安排随有效账单重算，已确认账单保留银行总额及快照，新补录标dirty待核对，禁止静默覆盖。
- 银行降额或撤销确认会造成超额时，须明确release_credit，超额转为未分配预还款，不改资金。恢复手动付款不能绕过dirty检查；自动付款按保留的银行金额重新抵扣。来源占用及已调整期次检查继续执行。
- 活动分期原消费资金字段受控；取消后重建须重新读取原消费的本金与账户。账期变更从最后确认账单次日生效，分期后续出账日跟随规则，账期区间不覆盖前期。
- 导入逐行SAVEPOINT，账户只取当前账本有效账户，转账/投资必须双账户不同；借入借出是单资金账户及独立借钱条目，不改成单边transfer。未识别账户需显式选择默认账户，失败原因写导入历史。AI还款候选引导金融核对，借钱中文主客体方向配回归。

## 定期记账

保留`/recurring`用于工资、房租及日常固定收支，订阅管理会员续费，金融模块管理借款计划及真实还款。`src/lib/recurring.js`统一手动/自动/API执行，以(rule_id,scheduled_date)唯一；重试复用原计划日期，不能改用已推进的日期。流水保存recurring_run_id，不依赖备注模糊查询。相似规则仅候选提示，用户确认后暂停旧规则并保留流水。金融调度只提醒，不生成真实付款。

## UI、API及验证

账户、借钱及`/finance`子页面统一1360px任务宽度上限，内容自然高度，窄屏单列；摘要自然分列、新建卡片与上方卡片总宽对齐，详情/归档等操作使用原有按钮组件并成组对齐，特殊银行逐期计划只在选中该方式时显示；表单按内容约束，长计划允许表格横向滚动，不设普通内容内部纵向限高。明暗主题、390/820/1280/1920/2560宽度、无JS表单、编辑/归档/恢复/差异变体共同检查；截图必须实际查看。

业务回归：verify-borrowing、verify-finance、verify-finance-api，并与所有既有套件一起跑run-all。浏览器脚本覆盖新入口及四组明暗/手机桌面无JS真实还款、更正计划、归档/恢复流程。只用隔离DATA_DIR，不触碰data/homeledger.db；Windows22/24及Linux CI必须绿。

Agent技能的维护主副本在skills/homeledger-bookkeeping，openclaw-skill下为相同兼容副本；主文档及references/finance-api.md须一起同步，用户只安装一份。接口、确认范围、幂等、授权和成功依据按实际实现更新；不因为技能更新扩大操作授权。

## 追加：记一笔还款及资金流

用户2026-11-11批准两套口径、默认资金流；src/lib/cashflow.js用SQL计算cash/debit/virtual/prepaid资金账户的净影响，自有资金互转抵销，待确认与adjust排除。消费、预算、年度消费报告和AI消费查询保持原消费口径并标注。首页两套口径同屏、报表可切换，资金流分组可查明细及分页，跨天日期按真实日期分组，日金额由SQL计算。API旧summary缺省保持消费，新调用显式basis=cashflow，两个对象均返回；详细接口同步技能参考。

记一笔的repayment为界面操作，不是交易类型；统一还款对象/付款API复用payments.repay，不另写流水。所有详情/编辑页的返回入口通过navigation.js与三种layout公共组件生成；仅当前页已校验对象决定父级，外部/脚本back参数不采信，不能依赖history.back。
