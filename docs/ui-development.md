# 界面开发与 Agent 验收约定

本文件是当前行为约束。历史设计与验收记录保留当时方案；发生冲突时，以本文件及维护者最新指示为准。

## 开始修改前

- 先读 `AGENTS.md`、`BOARD.md` 和所改页面的模板、路由、脚本。当前技术栈仍为 Express/EJS SSR 与原生 JS 渐进增强。
- `public/css/app.css` 是基础组件；后加载的 `public/css/workspace.css` 负责页面宽度、自然布局和明暗材质。修改已有规则，避免不断叠加互相覆盖的补丁。
- `layout.ejs`、`layout-m.ejs`、`layout-blank.ejs` 是三个入口；桌面页面通过 `.page-body` 约束内容宽度。`server.js` 的 `assetV` 同时维护两份 CSS 的版本/mtime 缓存戳。
- Git 目标先读 `git remote -v`；上游协作记录中的维护者、远端与部署地址不能作为本 fork 的操作目标。Git 网络操作仍按 SSH 规则执行，不因检查文档而推送或发版。

## 布局与材质

- 卡片按内容自然增高；不要用等高 Grid、固定高度或 `min-height` 填充无内容空间。大屏首页以独立列增加信息容量，普通表单与明细按任务约束宽度。
- 普通内容随整个页面滚动。分类网格和标签能换行就换行；不为排行、审计、分类列表、详情侧栏增加内部纵向限高。分页仍用于长流水，避免一次加载无限数据。
- 应用导航、下拉菜单、模态窗口、聊天记录具有自身交互边界，可保留必要滚动；窄屏财务表格可横向滚动以保持列对应关系。不要批量清除所有 `overflow`。
- 一级分类在内容上方完整平铺：桌面自适应多列、手机两列，长名称允许换行；子分类仅展示当前分组，编辑使用独立窗口，无 JS 时真实链接与原生表单仍可使用。
- 浅色和深色须分别检查背景、透光、高光、文字和按钮对比度。玻璃用于导航和控件，账务内容保持稳定表面。Web CSS 材质不等同原生实时折射，不声称“完全符合 iOS 27”或官方认证。
- 公共材质规则必须保留定位语义：桌面侧栏 sticky、手机/粗指针抽屉 fixed、菜单 absolute、移动底栏 fixed。移动断点为 `max-width:820px` 或 `pointer:coarse` 且 `max-width:1024px`。
- 通过 `hlEnhanceSelects` 增强新创建的原生 select，不克隆已增强的按钮/菜单。弹层须支持标签、键盘、Escape、焦点约束和返回；嵌套确认不能误关闭父窗口。保留减少动态、减少透明、高对比和无 JS 回退。

## 公共字体、按钮与导航（2026-11-11）

- 控件继承系统字体；常规操作使用 btn/btn-sm，危险操作用 btn-danger。不要在模板用10–11px字号或padding:0覆盖操作按钮。状态徽标、正文链接与操作按钮保持各自语义，字号层级通过公共令牌维护。
- 报表两种口径共用 partials/report-toolbar，标题、口径导航、日期和方向筛选结构一致，切换保留日期/年份与方向。新增报表口径不能复制另一套工具栏。
- 总览资金进出与消费收支两区同屏，共享月份，大屏并排、窄屏纵向自然排列；净资产、总资产与总负债以独立资产摘要卡清晰呈现，不能降为一行小字。资金趋势与消费趋势分别标注，消费构成和预算不混入还款本金。两套数据不相加。

记一笔新建页面使用entry-workspace共用宽度、导航与原生表单；类型与还款对象就地切换，保留适用的日期、金额及付款账户，原生无JS仍有真实链接/表单。切换前后需比较导航与卡片的文档坐标和宽度，并检查滚动条出现/消失。账户按分类分段、账户卡片平铺，避免分类账户数撑高其他模块；验收不同账户数量及编辑展开；相同模块入口全部用同类按钮，不能把字体相同当作设计一致的证据。

## 分类业务不变量

- UI 与开放 API 共用 `src/lib/categories.js`。内置分类可以编辑、软删除和恢复；`is_system` 是来源标记，不代表禁止修改。
- 第一次修改共享分类时，服务事务性生成当前账本副本并映射 ID；必须保留流水（含已软删）、预算、订阅、周期 JSON、习惯反馈及词典引用。禁止手写 SQL 绕过映射或修改其他账本模板。
- 删除保留历史引用；一级分类隐藏子树，恢复不撤销子分类各自的删除状态；恢复子分类前须恢复其父级。已有记录/计划可保留原已删分类，新建/新选不得使用已删分类。
- 已有二级分类编辑可调整所属一级：只允许同账本/同收支类型的有效一级，禁止升降级和绕过删除恢复；保留分类身份及历史引用。保存后导航到新一级并定位二级，界面说明历史汇总归属随之调整；无JS和开放API使用同一服务。
- 分类新建/编辑共用图标组件：常用图标平铺、更多图标按需展开，保留自定义表情输入和原icon字段；无JS用原生输入/datalist，隐藏无效按钮。取消后预览和选中态随原生reset复位。
- “调整顺序”模式支持一级与当前父级内二级的上移/下移。提交同组全部有效ID的完整顺序，旧模板ID通过事务映射；拒绝缺失、重复、跨组和归档ID；UI同时提交expected_ids，在事务内拒绝过期页面覆盖，已达目标顺序的重试仍成功。分类导航/记账/选择列表共用顺序，报表金额排行不变；保存后hash及焦点回到完整分类项，保留顶栏避让，名称与操作同时可见；无JS也能返回位置。
- 分类相关改动运行 `verify-categories.js` 所属全量回归，并检查表单、查询筛选、导入和开放 API 的实际调用路径。

## 本地预览与验证

| 用途 | 命令/端口 | 数据与说明 |
|---|---|---|
| 常规开发 | `npm start` / 5111 | 默认真实 `data/`，禁止用于测试写入 |
| 独立演示 | `npm run preview:ui` / 5112 | `.tmp/data-ui-preview/`；脚本可创建/补充演示数据，仅用于演示 |
| 业务回归 | `node test/run-all.js` / 8099 | 跑批自建隔离实例，数量以脚本为准；套件与断言数以当前输出为准 |
| 静态检查 | `node test/selfcheck-static.js` | EJS、JS、版本一致性；文档小改不要求重跑业务全量 |
| 浏览器验收 | `node test/verify-ui-browser.cjs` / 5113 | `.tmp/data-ui-browser/`；Edge 无头浏览器，脚本管理服务生命周期 |

浏览器验收依赖安装到本地忽略目录：`npm install --prefix .tmp/ui-qa --no-package-lock playwright`。默认 Edge 路径为 Windows 标准安装位置，可用 `UI_BROWSER_PATH` 指定其他兼容 Chromium 可执行文件。业务回归与浏览器验收按顺序运行，避免资源竞争造成启动超时。

公共 UI 变更需要更新浏览器验收的相关断言，并完成以下检查：

- 矩阵入口以脚本 routes 为准，不固定为历史的27个入口 × 5 宽度（390/820/1280/1920/2560）× 2 主题，另有 25 个起始状态、68 个设置/编辑变体；功能增加后更新覆盖范围，不把这些数字写成固定门槛。
- 设置标签须实际点击切换后检查对应面板；仅修改 URL hash 可能仍停留在原面板。检查默认页之外的编辑、无账本、只读、长名称、长备注、删除/恢复等相关状态。
- 检查内容剩余空白、阅读宽度、实际内部滚动、操作可达和焦点行为，并查看受影响页面的截图。不能只测 `scrollWidth`：移动抽屉参与布局也可能挤窄主内容却不溢出。
- 手机与触屏平板须检查抽屉计算定位和主内容 left/width；短屏详情通过整页滚动可到达末尾操作；同时检查键盘、200% 缩放与减少动态偏好。
- 测试仅修改隔离数据；只按已验证的 PID/命令行停止本任务实例。代码改动后重启实际使用的非 watch 实例，说明预览地址与未验证范围。

## 指引与技能如何同步

- 编码代理规则入口是根 `AGENTS.md`，本文件承载细节，不另建重复的编码技能。
- `skills/homeledger-bookkeeping/SKILL.md` 是给外部助手调用 API 记账的维护主副本，`openclaw-skill/homeledger-bookkeeping/SKILL.md` 是相同内容的兼容安装副本，不是 UI 编码指引。修改主副本后同步兼容副本并校验一致性；用户仅需安装一份。
- 分类接口口径必须同步可编辑、软删除、恢复及账本隔离；用户授权范围不因技能更新扩大。UI 样式改动无需复制到 API 技能。
- 具体变更证据见 [逐页验收记录](superpowers/validation/2026-11-09-workspace-polish.md)。后续发现共性问题，主动检查所有受影响入口，修复或登记看板，不等维护者逐页指出。

金融页面补充：账户、借钱台账及贷款信用卡使用可用工作区宽度，内容与编辑列按任务分配；金额与详情/归档操作分区，操作复用btn组件。金融列表独立纵向排列，登记区不等待相邻最长列表；银行逐期金额仅在选择特殊合同计划时展开。

## 自适应工作区与保存（2026-11-12）

- 报表、台账和管理任务取消固定窄页面上限；阅读、安全设置和认证页面继续保持合适宽度。1250px附近空间不足时，列表/编辑工作区回到单列，不保留300px主列。
- 表单按语义分配宽度：图标约72px、日期通常200px、名称与备注弹性；相关字段并排。订阅空态优先创建，年度/报表/导出使用独立自然列，不能仅拉长输入框填空。
- 模块边界由布局容器承担，账户集合至新增区24px；组内卡片间距单独管理，不依赖子卡片margin维持组外距离。测量跳过空异步占位节点。
- 记账分类一级完整平铺，仅展开当前组子分类；搜索同步原生select。隐藏选项不等于disabled，已有合法分类必须进入FormData；收入/利息默认收入组，编辑保留已有分类所属组，重复点击当前类型不能清空。
- 记账/编辑使用form属性绑定真实表单的固定操作条；还款对象更新后绑定同步。手机记账期间替换普通底栏，保留返回/菜单，预留内容、安全区和visualViewport键盘避让。无JS通过原生分类与固定原生提交按钮操作。
- 增强日期/选择隐藏原控件后，捕获invalid，展开details并把validationMessage及焦点映射到可见控件；不让保存停留在无反馈状态。有效提交才禁用重复操作。
- 浏览器`ui-workspace-checks.cjs`验证首中末保存可达、分类分组/保留、当前还款表单、24px边界、宽屏编辑器、日期宽度和错误定位；与原有明暗五断点、设置编辑和无JS矩阵共同执行。必须查看截图并执行实际任务，不用通过数量代替视觉结论。
- 完成任务后更新同一份日期_时间_任务名归档。此次证据与后续接续入口见[本轮归档](superpowers/validation/2026-11-12_11-23_全站自适应工作区.md)。
