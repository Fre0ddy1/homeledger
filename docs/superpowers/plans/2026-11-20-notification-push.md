# 通知中心与手机推送实施计划

**目标** 已有和新增的站内通知都能按接收人设置转发。同一通知可发往多个渠道，每个渠道独立去重和记录结果。

**架构** SQLite 持久保存配置和投递状态。站内通知写入后由后台读取并分发。设置页继续使用 Express、原生表单和 EJS。使用 Node 内置 HTTP、DNS、加密和 SQLite，无新增运行依赖。

**设计** [通知与推送方案评审](../validation/2026-11-20_17-10_通知与推送方案评审.md)

- [x] 在 `src/db.js` 的初始化中追加迁移，用 `auth.notify()` 保留已有站内通知并为新通知记录稳定类型。迁移时既有记录维持原状。通过隔离数据库测试旧表升级与重复初始化。
- [x] 在 `src/lib/push-channels.js` 实现三类请求构建、凭据加密和出网检查。使用本地可控 HTTP 服务验证 GET 查询、POST JSON 与表单、服务业务失败和超时。明确关闭重定向，固定已校验的 DNS 地址。
- [x] 在 `src/lib/notification-push.js` 实现设置、通知扫描、投递认领和重试。在调度器启动入口运行独立的短周期扫描。验证 `(notification_id, channel_id)` 唯一性、历史启用边界、重启恢复、失败隔离和发送记录脱敏。
- [x] 在设置新增个人渠道、通知选择与测试入口。日预算和信用卡提醒按现有账本管理权限设置。校验全账本、账户和分类范围。通过普通会话、CSRF 与不同账号的 HTTP 请求检验权限。
- [x] 在 `src/lib/notification-rules.js` 实现日累计预警与信用卡提醒配置，对已有订阅只标记通知类型。以受控时钟验证日预算 ¥300、80% 的阈值为 ¥240、同日重复检查产生一条、跨日重新计算。信用卡覆盖未确认出账金额与已还清。
