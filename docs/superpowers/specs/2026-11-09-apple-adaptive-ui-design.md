# HomeLedger 全站自适应与 Apple 风格 UI/UX 设计

日期：2026-11-09。状态：用户已审阅并批准，进入实施。

## 目标与范围

在现有 Express + EJS + SQLite、原生 JavaScript 渐进增强架构上重构全站展示与交互。保留现有路由、业务统计、登录、权限和记账流程。运行时依赖仍为现有三个包，不引入前端框架、在线字体或外网图表资源。此项目仍是 Web 应用，视觉与交互参考 Apple HIG / Liquid Glass，并不宣称具有原生系统渲染能力。

当前主内容 `.content` 被 `max-width: 1240px` 限制，这是宽屏大量留白的直接原因。首页已查询 `incomeCats` 却未展示；储蓄目标已有简易百分比，可增强展示而不新建数据模型。

## 方案取舍

1. **采用：保留业务层，重构公共设计系统与各页面布局。** 能延续现有 19 套测试覆盖，并逐批验证界面。
2. 仅扩大容器和调整颜色：改动较少，但不能满足全站 UX 重构和信息密度要求。
3. 更换为 SPA 技术栈：增加构建与部署成本，本次没有必要。

## 视觉系统

- 采用系统字体栈，中文使用平台系统字体；金额使用等宽数字。标题建立明显层级，正文默认 14–15px，不随屏幕宽度同比放大。
- 浅色以暖白/中性浅灰为内容底色、蓝色为主要动作色；深色使用分层深灰。收入与支出延续原有绿色/红色语义，并同时显示文字或符号。
- 大卡片圆角约 20–24px，控件约 10–14px；间距统一为 4/8/12/16/24/32px。阴影轻量、边界清晰。
- 玻璃材质用于侧栏、顶部工具栏、浮动导航和弹层背景。金额、表格和图表使用稳定的不透明或接近不透明底色。
- 提供 `backdrop-filter` 不支持时的实色回退，兼容减少动态效果、减少透明效果及强制对比度偏好；焦点环始终可见。
- 控件状态统一覆盖默认、悬停、按下、聚焦、禁用、处理中与错误。触控主要目标至少 44px，动效约 160–240ms，减少动态效果时取消非必要动画。

## 响应式与信息架构

以 CSS 视口宽度决定布局，而非按显示器物理英寸判断。27 英寸显示器可能因分辨率与缩放呈现不同视口。

- ≥1600px：侧栏约 240px，内容填满剩余可用宽度；首页采用三列，趋势/流水主区约占两列，其余模块按阅读顺序分布。
- 1101–1599px：侧栏与两列工作区，统计卡保持四列或按最小宽度换行。
- 821–1100px：紧凑侧栏/现有抽屉边界，主要模块按内容容纳能力降为一列或两列。
- ≤820px，及 ≤1024px 的粗指针设备：保留抽屉与底部导航。手机以单列呈现，统计卡可两列；已有极简模式继续可用并采用同一设计令牌。
- 内容边距随视口在 16–40px 内变化；容器不再受全局 1240px 限制。表单仍限制单行阅读宽度，将辅助说明/预览/统计安排到相邻区域。
- 宽屏填满可用横向空间，不强制每页填满垂直高度；避免人为放大卡片、字体或 SVG 图表补空白。复杂表格允许在表格容器内滚动，页面本身不横向溢出。

## 首页模块

1. 收支、结余、净资产：保留现有统计口径；前月无基数时显示“暂无可比数据”，避免误导的 0% 环比。
2. 收支趋势：近六个月；统一图表语义色、图例、主题和适当高度。
3. 最近记录：保留详情弹层、商家与备注展示，提供全部记录入口。
4. 支出构成与新增收入构成：复用 `categoryBreakdown`，显示类别、金额和占比；空数据有明确说明，不制造演示金额；分类点击进入现有筛选页面。
5. 储蓄目标完成率：显示目标名、百分比、已存/目标金额、剩余金额与管理入口。百分比对零目标做保护，进度条限制 0–100%，超额金额仍按真实数值展示；无目标时显示创建入口。
6. 今日速览、预算执行、订阅扣费、账户余额、待报销、借贷与周期账单：保留现有功能，在大屏合理安排到辅助列，窄屏依次排列。

所有新展示只读复用当前账本数据，遵循当前账本 ID、角色和金额单位（整数分）。只读用户不出现记账/创建等写入入口。

## 全站页面覆盖

- 公共骨架：`layout.ejs`、`layout-m.ejs`、`layout-blank.ejs`，统一侧栏、顶栏、底部导航、用户菜单、闪现通知。
- 日常记账：总览、手机首页、明细、记账表单、日历、搜索、AI 识别与草稿、附件。
- 分析与计划：报表、年度账单、账户及详情、预算、目标、订阅、周期账单、借贷。
- 数据与协作：分类、标签、导入、导出、账本、成员、通知。
- 系统与起始状态：设置、关于、登录、注册、初始化、加入账本、无账本、更多、错误页。

公共组件更新后逐页检查布局和状态，不能仅给首页换皮便认定全站完成。必要时提取专用 partial，避免大型页面继续膨胀。

## 交互与状态

沿用已有渐进增强机制。菜单、选择器、确认与详情弹层支持键盘操作、Esc 关闭、焦点返回；移动端弹层避让安全区和软键盘。危险动作保留原有确认。所有表单保留 CSRF、可见标签和错误信息。AI 配置缺失/处理中/失败/空草稿等状态沿用现有真实行为。静态资源继续使用版本和 mtime 缓存戳。

## 实施批次及验证

1. 公共令牌、组件与三套布局；完成全站共同视觉基线。
2. 首页结构与收入构成/储蓄目标，验证空数据、正常数据、零分母、长名称和只读成员。
3. 逐页调整专用布局、图表、表单、列表及移动端交互，检查全站页面覆盖表。
4. 新功能补充 `test/verify-*.js` 并登记 `test/run-all.js`；静态自检与全部回归必须通过；独立审查后修复问题。

视觉验收覆盖 390、820、1280、1920、2560 CSS 像素宽度，浅色与深色；补测 200% 缩放、键盘操作、减少动态效果。确认页面无横向溢出、主内容填满宽屏剩余空间、金额可读、表单不过度拉宽、导航不遮挡内容。

调试仅使用隔离 `DATA_DIR`，不接触真实账目。所有代码留在功能分支，本次不推送、不合并、不打 tag、不部署。
