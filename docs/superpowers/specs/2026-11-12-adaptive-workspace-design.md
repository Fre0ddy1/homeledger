# 全站自适应工作区与表单操作设计

日期：2026-11-12。状态：维护者已明确确认并实施；实际执行、验证和交付结果见[持续归档](../validation/2026-11-12_11-23_全站自适应工作区.md)。下文保留设计阶段的调查和决策依据。

## 1. 本轮任务、假设与成功标准

维护者指出：记一笔分类太长、保存难以触及；账户新增区紧贴列表；资金流报表信息少且纵向堆叠；订阅等页面两侧留白、编辑栏窄、日期等短字段过长。要求逐项说明原因、提出统一方案，并排查修复全站同类问题。

本轮按现有 Express/EJS/原生 JS 渐进增强方式改造，不更换前端框架。保留当前明暗设计语言、账户资格、资金流/消费两套口径、自动还款与草稿保留规则。宽屏以浏览器可用宽度判断，不以显示器英寸判断。

成功标准：长表单的主要提交操作在滚动中仍可达；宽屏用并排的信息与字段减少滚动，短字段不随整卡拉长；内容卡片自然高度，各模块有明确间距；手机、键盘与无 JS 操作仍完整可用。

## 3. 根因与前期验收遗漏

### 分类与保存

`txn-form.ejs` 同时渲染所有一级分类下的子分类。一级分类点击调用 `scrollIntoView`，没有切换当前分组，因此它是长列表的定位入口。保存卡片放在分类列表之后，直接继承了整棵分类树的高度。手机变为单列后更长。

分类管理页已有“一级完整平铺、只展示当前组子分类”的规则，但记账分类选择没有采用同等交互。前期对分类管理的局部验收没有追踪到记账选择入口。

### 账户间距

`.account-cards` 为卡片网格，子卡片 `margin:0`，组内由 `gap` 提供间距；该组容器不是 `.grid`，没有获得 `.page-body > .grid` 的下方间距。紧随其后的 `#new-account` 没有上方间距，出现“组内正常、组与组紧贴”。不能依赖前一张卡片的下边距来维持模块间距。

### 宽屏与长表单

`workspace.css` 将订阅、周期等页面限制为 1200px，多数 `.grid-main` 的右列限制为 320–380px。原本用于限制阅读宽度的规则也作用于包含列表、编辑器和图表的工作页面。字段又大量使用 `flex:1` 或单独一整行，结果两侧留白与内部长表单同时存在。

报表使用相同的问题模式：顶部筛选、多张摘要、整行趋势、构成列表依次向下排列；资金流模板仅呈现三项汇总、月趋势和流入/流出分组，没有把现有每日数据、对比和占比用于分析。

### 为什么测试未发现

现有矩阵主要自动检查横向溢出、字体继承、内部滚动、导航及部分控件行为；首页列间距有专门断言，但账户列表与新增模块的边界没有断言。UI 文档虽然要求检查操作可达与空白，测试没有量化保存按钮位置、宽屏利用方式、字段长度和相邻模块间距，也没有按完成一笔记账的路径进行长分类测试。

因此，这是设计约束覆盖不全以及验收执行遗漏。之前“全量回归通过”只能说明当时检查项通过，不能证明布局与任务体验已经完整。此次补充测试必须能在旧实现上复现这些失败，再证明新实现修复。

## 4. 可选方向与推荐

| 方向 | 收益与代价 |
|---|---|
| 只放宽页面最大宽度 | 改动少，但长分类、保存位置和字段比例依旧不合理 |
| 自适应工作区＋语义字段网格＋可达操作区（推荐） | 复用原模板和组件，有针对性调整页面结构，同时解决宽屏、滚动和操作问题 |
| 全部改为弹窗/分步向导 | 可缩短单屏内容，但大量新增步骤、焦点和草稿状态，本轮没有必要 |

推荐第二种，不引入通用表单框架或新的前端依赖。

## 5. 统一布局约定

- 列表、报表、台账、分类、附件等工作页面使用主内容区域可用宽度，保留稳定的页面内边距，不再套用 1160/1200/1360px 的统一窄上限。
- 内容内部根据任务分列：宽屏主区与辅助/编辑区约 3:2；表单编辑区目标约 560–760px，主区获得其余空间。空间不足以容纳两个可读列时改为单列。以容器的实际可用空间决定断点，不硬塞两列。
- 单纯阅读、登录和少量短字段的安全设置保留合适阅读宽度；多个独立设置卡片可以并排，不能把密码框、说明段落横向拉满。
- 字段按用途分配宽度：图标约 64–80px，日期/月约 180–220px，币种/状态等短选择约 100–160px，常规金额约 160–220px；名称与备注获得弹性宽度。窄屏不强制最小宽度，保证完整日期可读。
- 编辑器宽屏通常 2–3 列相关字段；手机按阅读顺序一列，金额＋币种等短字段在放得下时并排。不能机械规定“每行两个”等宽格子。
- 同组字段间距 12–16px，同层卡片间距 20px，独立模块间距 24px；通过明确的布局容器承担 `gap`。使用这些容器的卡片不再叠加旧的外边距。
- 独立纵向内容列不为相邻列补齐高度。不加空卡片、不设内容限高、不新增内部纵向滚动。按视觉列排列时保留可预测的 DOM、阅读和键盘顺序。
- 主按钮、次按钮、危险按钮继续复用现有组件与字体令牌；同类详情/查看入口使用一致按钮形式。材质沿用现有明暗主题，不在本轮再建立一套视觉系统。

## 6. 逐项交互设计

### 6.1 记一笔：分类分组选择＋持续可达的保存

1. 一级分类全部自然换行平铺，不做横向或内部纵向滚动。点击一级分类只更新下面的子分类区域，不跳动页面。只展示当前分组；已有分类时打开对应分组，未选时展示首组但不自动替用户选分类。
2. 可搜索完整分类路径，搜索结果自然展开；选择结果后同步一级分类与当前路径。保留“不细分”。切换分类分组不清除已经选定的分类。
3. 桌面左侧为金额、账户、日期等主要信息，右侧为分类选择与当前记录摘要。AA、多币种等选填内容保持明确可展开入口，不让选填内容占据默认主流程。
4. 新建与编辑记账使用独立于长内容的固定底部操作条，显示当前类型/金额、保存和取消。操作条对齐主工作区；页面末尾预留相应空间，不能遮住最后一个字段。
5. 手机进入记账/编辑任务时，底部普通导航位置切换为“取消/保存”操作区，保留顶部返回和菜单入口，避免两层底栏叠在一起。离开任务恢复普通导航。覆盖安全区、键盘弹出和横屏。
6. 支出、收入、转账、借钱、还款复用同一操作区外框；提交绑定当前实际表单。切换还款对象后，提交目标、文案及摘要必须一起更新，禁止误提交隐藏草稿。
7. 原生校验失败时定位首个错误字段并保留全部输入；有效提交后阻止重复点击。无 JS 使用原生分组分类选择与真实提交表单，不能依赖 `href="#"` 完成分类输入。

### 6.2 账户管理：明确模块边界、减少多余字段

1. 为账户摘要、账户集合、停用集合、新建账户定义显式的模块间距，修复 0px 间距，不靠一张卡片的偶然 margin。
2. 账户卡片按可用宽度排 1/2/3 列。编辑展开时继续自然增高；必要时让正在编辑卡片占完整任务行，避免一个长编辑器在另一张短卡片旁制造大块无意义留白。
3. 新建账户按“名称/类型/图标”“余额/币种/备注”组合，图标和金额不等宽拉长。额度、账单日、还款日只在信用卡类型下展示；保留服务端及无 JS 可用路径。
4. 添加入口与表单使用同一标题、按钮组件和对齐边界；保留停用/恢复及金融账户保护。

### 6.3 报表：左侧解释资金去向，右侧展示图表

宽屏结构如下，窄屏按相同信息顺序纵向排列：

| 全宽区 | 内容 |
|---|---|
| 紧凑工具栏 | 两种口径、日期区间、方向筛选，共用原工具栏 |
| 摘要行 | 资金流出、资金流入、净变化、流出笔数/笔均流出 |

| 左侧约 60% | 右侧约 40% |
|---|---|
| 资金流出用途与排行：金额、占比、笔数、明细入口 | 所选期间每日流入/流出趋势 |
| 资金流入来源与排行 | 流出构成图与图例 |
| 本期与上期对比，清晰标注比较区间 | 近 12 个月趋势，明确截止月份 |
| 选中分组的分页明细 | 同期消费收支参考摘要（独立口径） |

- 资金流目前已有“流出”总额，问题在于分析维度与布局不足，不能误称目前完全没有支出数据。
- 用途呈现日常消费分类、信用卡还款、贷款还本、亲友还款、借出、投资转入、利息/手续费等现有真实分组。空分组不伪造记录；各分组金额合计与同口径流出一致。
- 补充流出占比、笔数、笔均、期间日均、最大流出日及可比期间变化。零分母、无上期数据显示“—”，不制造 0% 增长等误导。日均以所选区间内截至今天的自然日数计算并标注截止日；纯未来区间显示“—”。已完成月份对比上月，当月对比上月同进度（月底钳制），自定义区间使用紧邻等长前期，并展示实际起止日期。
- 消费收支参考单独标明“同期消费”，可解释刷卡消费与实际还款的时间差；它不与资金流相加，还款本金不计为第二次消费。
- 现有 `cashflow.daily/summary/breakdown/monthly` 和消费汇总优先复用。短区间日趋势、长区间按月聚合，避免年度图表塞入数百个点；期间对比使用同口径和明确的等长前期/月度前期。
- 消费收支报表采用同一工作区骨架，把同期对比、分类排行、成员/归属人放在信息列，趋势与分布放在图表列。保留已有下钻、筛选和分页。

### 6.4 订阅与其他长侧栏表单

- 订阅不再采用 380px 窄侧栏。已有订阅时列表与较宽编辑器并排；无订阅时优先展示创建工作区，空状态成为简短引导，不占据宽大的空列表列。
- 宽屏将图标、名称、套餐说明组合在一行；金额、币种、计费周期组合；下次扣费日、状态、提前提醒组合；账户、分类并排。名称/套餐空间不足时自然换行，标签与含义保持独立。
- 试用结束、管理页地址、备注归入明确的可选信息分组；编辑已有非空选项时自动展开。到期自动记账开关和解释不隐藏。
- 常用服务快选折成紧凑的推荐入口，展开仍可看到全部；选择预设不覆盖用户已经编辑的金额、账户等不相关数据。
- 周期记账、预算、储蓄目标、借钱登记采用同类布局，编辑区可容纳相关字段并排；每页仍保留自身业务字段，不建立万能表单。
- 金融首页改为独立的台账内容列与登记编辑列，避免两张不等高列表占据同一 Grid 行、跨列登记必须等最长列表结束。贷款/信用卡详情保留计划与真实资金信息，日期、金额及账户字段合理并排，高级校正仍按需展开。
- 多表单管理页的按钮属于自己的卡片；不全站套用一个无法区分提交对象的悬浮保存按钮。持续可达操作条先用于明确的记账/编辑任务，其他表单通过宽布局和缩短主流程解决。

| 导入（实测） | 卡片间距20px通过，动态预览需容纳表格 | 上传/账户设置与说明并排；预览与历史利用宽屏 |

| 账本（实测） | 新建/编辑字段的宽度依赖零散内联规则 | 名称弹性、币种/图标/排序定宽，保留主次动作 |
| 成员（实测） | 列表、邀请、权限说明可并排 | 列表主列＋邀请/说明辅助列，长链接可换行 |
| 设置六标签（补查） | 不同上限，安全/AI/站点表单目的不同 | 独立设置块并排；密码/Key/URL不机械整页拉宽 |
| 附件（实测空状态、源码记录态） | 画廊能自然增列，查看入口样式需统一 | 内容区利用宽屏，查看记录按钮统一；保留分页 |
| 通知/更多（实测） | 阅读与导航内容，不适合强行加宽文字 | 保留阅读宽度，复核卡片间距和统一入口 |
| 关于（实测） | 长度来自历史更新日志 | 保持阅读宽度；本轮不因内容长而删改历史 |
| 登录/注册/初始设置/邀请加入/无账本/错误（源码） | 单任务或状态页面 | 保持适合阅读和输入的宽度，纳入公共CSS回归 |
| 极简手机首页与三种layout（源码） | 独立移动入口/导航 | 不套桌面宽屏规则；重点检查操作条与底部导航关系 |

## 8. 防止重复遗漏的验收机制

1. 建立按页面类型的检查清单：工作区利用率、字段宽度、模块边界、主要操作可达、空/有数据/长数据、编辑/只读、明暗主题、手机与宽屏。截图必须等入场动画结束，不能把动画中间帧当最终视觉。
2. 为本轮问题增加有针对性的断言：账户集合与新增区间距24px；记账顶部/中部/底部均能访问当前有效提交按钮，按钮不被底栏遮挡；分类只展示当前组、一级全部可达；宽屏订阅不再是380px侧栏；日期可读且不占据大段整行。
3. 间距测量按相邻可见内容区域判断，跳过空的异步结果占位；排除菜单、辅助节点、隐藏表单，避免本轮出现过的误报。
4. 每页保存实施前后同视口截图与关键任务结果，不仅测试没有溢出。宽屏目标包括首屏信息量、完成创建所需滚动、卡片之间空隙来源；不以“所有空间必须填满”制造填充内容。
5. 新建与编辑、只读、空列表、长名称/长备注、多账户数量、分类大量增加、手机键盘、200%缩放、无JS都列入相关验收。浏览器仿真不能代替物理手机键盘，未完成的真机项明确标记。
6. 将新约定落实到 `docs/ui-development.md` 与已有浏览器验收，不增加与规则文档重复的UI技能。API统计行为变化时同步接口与两份API技能；纯CSS不复制到API技能。
7. 独立审查须同时检查产品操作路径与代码，全部必要测试通过后按既有授权创建PR并合并main。标签和镜像不属于本轮。

实施后的命令：`node test/selfcheck-static.js`、`node test/run-all.js`（Windows22/24及Linux CI）、`node test/verify-ui-browser.cjs`。执行仍使用隔离目录；套件数量以当前脚本为准。

## 9. API、数据与边界

已有 `/summary`、`/cashflow`、`/reports/categories`、`/reports/trend` 提供双口径、每日数据、趋势与构成。展示占比和日均不需要新建写接口。优先复用公共服务；若新增比较字段或历史趋势锚点，同批修改读接口、验证与两份Agent参考，避免UI和API口径漂移。

本轮不改变已批准的自动还款、本金分类、账户资格、真实交易状态、币种换算及删除恢复规则。不自动代用户产生实际付款。统计全部来自数据库/服务计算，货币用整数分；日均等展示数按明确规则舍入。

覆盖零记录、零分母、负净值、退款、预还款、跨年、历史日期、短屏、长文本与只读。大量流水继续分页；不为了缩短页面一次加载全部历史，也不靠内容区内部限高隐藏信息。
