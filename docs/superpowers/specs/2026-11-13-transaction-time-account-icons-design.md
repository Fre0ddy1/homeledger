# 分类Emoji、交易发生时间与账户类型设计

日期：2026-11-13（Asia/Shanghai）。状态：方案A已实施并通过验证，PR #9已合并main。实际交付357个Emoji、13个场景。

## 现状与问题

1. 分类新建/编辑共用category-icon-picker.ejs，目前96个Emoji，其中24个常用。已有自定义输入和无JS datalist，但场景覆盖和检索能力不足。
2. transactions保存txn_date（业务日期）与created_at（实际录入时间），没有txn_time。手动表单已有type=date，开放API已有date/txn_date，并非只能使用创建当天；缺失的是时分秒和清晰展示。API目前把非YYYY-MM-DD日期静默回落今天，不能直接传日期时间字符串。
3. TXN_SELECT已有付款账户account_type，转入账户没有类型；共享交易列表和详情JS只展示名字。ACCOUNT_TYPE_MAP已有储蓄卡/信用卡等中文标签，可以直接复用。
4. 参考仓库README确有txn_time（HH:mm:ss）与消费日分离的设计，并记载CSV导出/回导时间遗漏的修复；本轮借鉴其时间语义，不移植Vue或存储架构。来源：https://github.com/huangge1199/homeledger/blob/main/README.md。

## 方案选择与推荐

- 方案A（推荐）：交易日期＋可选时刻，录入时间独立且不可改写；不知道几点就保持未知，禁止拿创建时刻补齐。
- 方案B：新建默认当前时刻且允许修改，操作更少，但补记往日且忘记修改时容易形成虚假精确时间。
- 不采用每笔强制时间：历史账单、自然语言和定期账单经常只有日期，强制输入会迫使用户猜测。

维护者已明确确认方案A：未知时刻留空，按整体方案实施。

## 1. Emoji选择

- 候选扩充至300余个，优先覆盖食材/饮食、服饰美妆、住房日用、交通车辆、医疗健康、学习工作、娱乐运动、旅行住宿、育儿家人、宠物动物、收入理财、人情公益等分类场景。
- 保留24个常用快捷项；更多候选按场景分组，提供中文名称/同义词搜索。搜索只影响候选显示，不改变已选图标或表单其他内容。
- 新建和编辑仍共用同一组件和候选数据；普通区域自然换行，保留既有模态边界，不新增普通内容内部限高。
- 无JS保留输入与datalist，所有候选可查；未命中可输入/粘贴系统Emoji。取消后输入、预览、选中态及临时搜索复位。
- 不依赖外部网络或图标包。已有图标不删除；去重并验证现有maxlength8能接纳所有预设值，不额外修改自定义长度规则。

## 2. 交易发生时间

### 数据与语义

- 保留txn_date作为交易发生日，新增可空txn_time作为该日时刻；以本实例配置时区解释，当前部署口径为Asia/Shanghai。不是创建时间，不独立偏移消费日。
- 输入接受HH:mm或HH:mm:ss，校验后统一存HH:mm:ss；分钟输入仅显示到分钟即可，秒非零时显示秒。未知存NULL，界面显示“未提供时刻”，不得填00:00或复制created_at。
- created_at保留真实录入审计值，详情改用清晰文案“录入时间”；更新不能重写created_at。旧记录保留已有txn_date，txn_time未知，不从created_at回填。
- 新增数据库字段只在隔离实例验证；不直接执行真实账本迁移或编辑真实流水。

### 手动创建与编辑

- “日期”明确为“交易日期”，并排增加“交易时刻（可选）”，默认留空；提供“此刻”快捷操作，只有点击时才同时填当前日期与时刻。
- 时间可独立清除；编辑带出原值。类型切换、普通记账/还款往返、验证失败和无JS提交保留适用的日期与时刻；固定保存区继续绑定真实表单。
- 还款和亲友借钱流水使用其公共服务接收实际时刻；关联已有流水时保留来源事实，不用本次核销创建时间替换来源交易时刻。付款更正、撤销/恢复及幂等参数一并核对，不能绕过资金保护。

### 开放API与Agent

- 普通交易创建/更新接收date（兼容txn_date）和time（兼容txn_time），例如date=2026-11-12、time=18:35:20；不新增平行入账接口。
- 创建未传time则为NULL；局部更新未传保留，显式null或空串清除。非法日期/时刻给清晰错误，不悄悄改为今天或创建时刻。
- 列表、recent、单笔详情、创建/更新回执与相关金融接口返回txn_date、txn_time、created_at的明确语义；不删除已有字段。
- ping补充实例时区/当前时间供调用方确定相对日期，保持today。API日期和时刻按实例时区解释；本轮不另建多时区记账设置或无约定的ISO时间别名。
- 两份Agent技能及必要金融参考同步：用户指定时刻必须传递；截图读取真实时间；仅“昨天午饭”“昨天下午”等不能臆造12:00/15:00；回执区分实际交易时间与录入时间。

### AI、导入导出与其他写入

- AI结构、模型提示、规则降级、草稿编辑/确认、聊天与开放AI入口贯通txn_time；有依据才提取，未知空值。缺Key仍可使用已有降级路径。
- CSV/账单导入提取完整“交易时间”，自家CSV新增独立“时间”列并支持回导；日期与时间分列时精确识别，不能把完整交易时间列误当独立时间列。导入预览、去重与错误反馈同步核对。
- JSON现有导出保留时刻，CSV现有回导不丢失；当前没有JSON/Excel回导接口，不为本轮另建新接口。重复判断在有可靠时刻时区分同日同商家同金额的不同消费，未知时刻不能编造来绕过去重。
- 定期/订阅等只有计划日期的系统入账继续保留未知时刻，不把调度执行时间当消费发生时间；有真实来源时保留来源时刻。

### 查询与展示

- 共享流水列表在日期分组下显示已知时刻；详情明确“交易时间：2026-11-12 18:35”和“录入时间：2026-11-13 …”。未知时刻只标注未提供，不用录入时间替代。
- 默认日期排序内按已知实际时刻排序，未知在该日已知记录之后；同刻/未知用ID稳定排序。日期升序同样确定未知位置，不影响金额排序。
- 总览/搜索/账户/日历及金融关联流水检查共享列表与其他变体，保持字段一致。
- 月/日统计、预算、现金流与信用卡账期仍以txn_date归属，不因时刻字段改变金额或统计口径。

## 3. 账户类型可见性

- 共享查询补齐to_account_type，统一从ACCOUNT_TYPE_MAP派生账户类型中文标签，避免前端另写不一致映射。
- 流水列表名字旁增加轻量类型标识，例如“招商银行 · 信用卡”“工商银行 · 储蓄卡”；转账分别标明两端类型。
- 详情明确显示账户名＋类型，付款来源和收款目标分别对应；未指定账户不伪装成现金，停用账户的历史流水仍显示真实类型。
- 记账账户选择和相关交易API返回同步账户类型，帮助Agent和用户辨别同名账户；沿用账户资格规则，不扩大可选账户范围。
- 明暗主题、手机换行、长名称、转账双边和无账户状态均验收，复用既有字号、徽标和按钮。

## 成功标准与验证

- 今天补记昨天18:35的账，手动/API/AI/导入得到一致发生日与时刻，列表排序正确，录入时间仍为今天；仅知道日期的账不显示虚构时刻。
- 覆盖创建、局部更新保留、显式清除、非法值、秒、闰日、相对日期、未知时刻、同刻排序及CSV回导与JSON导出；金融关联、幂等、更正/撤销恢复和统计口径不退化。
- 信用卡/储蓄卡及转账两端类型在列表、详情、相关选择和API中一致；账本隔离/只读权限不改变。
- 300余个Emoji可按场景和关键词找到，键盘/鼠标/触屏选择后正确保存，已有自定义表情保留。
