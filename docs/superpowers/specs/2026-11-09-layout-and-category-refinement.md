# 第二轮：布局、玻璃材质与分类恢复

用户已确认一起解决首页空隙、明细过宽、玻璃效果不足，并追加内置分类可编辑、删除后可恢复。沿用已批准的后端和公共组件架构，当前分支继续开发。

## 实现约定

- 首页模块按 main / analysis / plans 分组。桌面三列各自堆叠，中等宽度两列，窄屏恢复原始卡片顺序。JavaScript 仅移动原节点，无 JS 时使用 CSS 分栏，保留所有内容。
- 明细主栏最高 1100px，右栏展示筛选摘要与详情；小于 1200px 使用原有详情弹层。右栏按视口约束高度、内部滚动。金额和操作列对齐，默认每页 20 条，可选 40/80，查询条件跨筛选和分页保留。
- 导航、侧栏、菜单采用更低不透明度、边缘高光、分层阴影与鼠标高光；保持实色内容卡片及减少动态/透明效果回退。这是 Web 材质实现，不宣称复刻原生系统的折射渲染器。
- 所有分类均软删除，不提供永久清除；历史引用保留。删除一级分类仅隐藏子树，不改变子类自身删除状态；恢复父类不会复活曾单独删除的子类。恢复子类前须先恢复父类。
- 系统模板全站共享且不直接修改。首次修改/删除时，事务内为当前账本复制共享分类，记录 `category_copies` 映射；同步流水（含已删）、预算、订阅、周期 JSON、私有分类父级、词典与习惯反馈中的引用。
- 选择器、AI、导入、API、旧 ID 读取使用统一解析。已有账单和计划可保留原已删除分类，新建或新选不能使用已删除分类。按分类预算不允许空分类导致统计范围扩大。
- 只读/跨账本保护、CSRF 与审计保持；恢复旧 SQLite 备份时补齐新增映射表和字段。测试只使用隔离数据，不操作真实账目。
