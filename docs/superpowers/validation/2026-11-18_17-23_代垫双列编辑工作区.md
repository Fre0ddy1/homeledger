# 代垫双列编辑工作区

## 目标与决策

维护者要求按「记一笔」重新设计代垫编辑页，桌面采用左右两列。承接 `codex/advance-edit-navigation` 的 `9071aee`，继续使用当前模型。保留三份已有未跟踪归档。

- 使用现有编辑入口和 `?edit=1` 生成独立工作区。左侧集中付款信息，采用记账大金额样式。右侧分为分类、备注与标签两张自然高度卡片，同一表单一次提交。
- 复用记账的 `.grid-main`、按钮和固定保存条。完整布局 1250px 以下及手机极简界面自然单列。金额更正规则、权限、提交地址和 API 契约保持现状。
- 取消与返回均指向代垫详情。正常详情保留付款分项、回收和撤销操作。编辑页隔离回款草稿，校验失败继续回填编辑内容。无 JavaScript 时保存条仍绑定真实表单。

## 实施与验证

- `src/views/advance-edit.ejs` 独立模板，`advance-detail.ejs` 保留编辑链接。`src/routes/advances.js` 和 `src/lib/navigation.js` 按编辑与详情模式提供视图及返回目标。
- `entry-actions.ejs`、`public/js/app.js` 增加固定绑定场景，沿用防重复提交与恢复。`workspace.css` 的局部布局只影响代垫编辑，手机极简时以保存条替代底栏。
- `ui-advance-checks.cjs` 验证两列横向对齐、窄屏纵向、实际表单绑定、取消返回、极简与无 JS。保留分类、草稿回填、实际金额更正和回款旅程。
- Windows Node 24 全量 32 套、1725 项通过，静态自检 15 项通过。初次浏览器运行命中标签可访问名称的模糊匹配，改用精确标签后聚焦 8 组通过。实际查看了浅色桌面和深色手机，随后收紧卡间距与日期时刻布局。
- 独立代码复审无 P1/P2。5112 预览已换为本轮 PID 35768，仍沿用本地隔离演示账本。
- 使用 5112 预览在默认动效下实测 1920、1280、1250、820 和 390 宽度，发现 `.content` 的进场位移动画暂时改变了固定保存条的包含块。仅在代垫编辑页停用该动画，复测五种宽度的列数、首屏保存可达及无横向溢出均通过。最终桌面与手机证据为 `.screenshots/audit-after/advance-editor-final-desktop.png` 和 `advance-editor-final-mobile.png`，均已查看。
