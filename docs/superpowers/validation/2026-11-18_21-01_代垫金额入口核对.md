# 代垫金额入口核对

## 目标

核对上一轮统一编辑后，为什么账单列表的「自用／代垫」仍可打开独立回收页，并评估入口优化方案。

## 现状和原因

- 本地基线是 `c62d87a`。上一轮将付款行右侧操作区的「编辑代垫」换成普通编辑和删除，回款模块放进共用账单编辑页。
- `src/views/partials/txn-list.ejs` 里的金额摘要是另一处链接，仍指向 `/advances/:id`。该局部模板同时用于账单明细、账户详情、现金流、首页最近记录和搜索。
- `public/js/app.js` 的账单详情面板也为付款主单提供「管理代垫」链接。旧浏览器验收还通过行内摘要直接打开独立详情，上一轮没有验收两条入口是否统一。
- 独立台账仍展示付款分项、原始附件和历史记录，支持整体撤销后的恢复及只读查看。编辑路由要求账本写权限，手机版账单明细的行内操作由详情面板承载，关闭 JavaScript 时需要原生入口。

## 方案

推荐在账单明细的代垫付款主单行将「自用／代垫」金额改为和账户、备注一致的普通文字，保留已收齐、部分回款和待收状态。点账单行沿用普通详情，有写权限的用户点「编辑」进入共用页，从分类下处理回款。同步收拢可编辑主单在详情面板里的重复管理操作。只读和无 JavaScript 路径保留明确、可用的原生查看或编辑入口。侧栏代垫台账继续负责集中查询和历史恢复。

另一方案是把金额链接改成直接跳转共用编辑页的回款区。它省一次点击，但会和编辑图标重叠，仍须对只读角色单独处理目的地。

## 验收建议和状态

验收覆盖桌面、手机、只读和禁用 JavaScript 的记录查看与编辑路径，断言付款主单的金额摘要是普通文字，待收及已收齐状态仍直接显示。账单筛选回跳、独立台账撤销恢复和共用局部模板的其他调用者同步核对。

## 实施记录（2026-11-18 21:10 起）

1. 维护者回复「开始优化」，沿用推荐方案。用 `src/views/transactions.ejs` 的显式参数约束 `txn-list.ejs` 局部模板，只处理账单明细内的代垫主付款行。这些行以原生 `span` 渲染金额，保留回款状态徽标和普通操作图标。
2. `public/js/app.js` 在主单的普通详情内展示代垫对象和回款进度。可写用户使用共用「编辑」，只读用户使用「查看代垫详情」。在 `noscript` 提供只读查看和窄屏编辑链接，桌面无脚本沿用原有编辑图标。
3. 修改 `test/ui-advance-checks.cjs`。金额文字点击验证普通详情和后续共用编辑；无脚本手机用真实链接。只读路径使用隔离账本内的真实邀请和只读角色，校验无法打开编辑页。独立详情改由「代垫与回收」台账进入并继续验证历史恢复。首轮 8 组明暗、手机和桌面、JS 和无 JS 实测全通过。
