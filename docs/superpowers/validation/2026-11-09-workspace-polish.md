# 全页布局、分类工作台与明暗材质复核

日期：2026-11-09。分支：`feat/apple-adaptive-ui`，仅本地开发，未推送、合并或发版。
沿用已批准的 Apple 风格 UI 方案，按维护者第三轮实测反馈修正。

## 问题与处理

此前全局 Grid 默认拉齐卡片高度，大屏通用比例又让侧边表单过宽。1920px 演示数据中，分类两栏均高 7776px，收入栏底部有 6235px 无内容空间。改为自然高度与按任务约束宽度，首页继续独立多列，其他页面不以铺满显示器为目标。

| 页面 | 本轮约束与检查 |
|---|---|
| 首页 | 保留全宽独立三列、两列、单列顺序和 20px 间距 |
| 明细 | 工作区上限 1464px、流水主栏 1100px；内嵌详情短屏可滚动 |
| 新建及编辑流水 | 两种入口均限制工作区 1280px，主辅列按任务分配 |
| 报表、年度报告 | 1320px，图表适配容器，卡片自然高度 |
| 日历、预算、目标、借贷、成员 | 1160px；侧边表单 320–380px，窄屏单列 |
| 周期账单、订阅、AI、搜索 | 1200px；周期表单侧栏 420px，四个重复项控件分两列 |
| 账户列表及详情 | 1280px，自适应账户卡片，新建表单卡片 980px |
| 分类 | 1280px，一级分组导航＋当前子分类卡片；手机水平分组导航 |
| 设置 | 工作区 1180px；AI/站点卡片 840px，API 1080px，其他单卡 960px |
| 标签、通知、更多 | 960px |
| 导入、关于、导出、账本 | 分别 1040/1040/1120/1080px |
| 登录、注册、初始化、加入账本、无账本、404 | 检查宽度和空状态；匿名认证页面支持系统深色偏好 |

分类编辑采用有标签和焦点约束的独立弹层，关闭回到原分类；删除仍二次确认并保留可恢复数据。新建时父分类按收支类型过滤；保存后定位修改项。无 JavaScript 时保留真实分组链接、搜索和原生 details 表单。仅渲染当前分组，避免全部分类编辑器堆成长页。

修复增强下拉菜单外部点击关闭后内部状态不同步，以及按 Escape 时误关闭父弹层的问题。修复周期账单“再加一项”克隆已增强下拉导致新控件无法操作的问题。

## 官方规范对照与边界

参考 [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 与 [Liquid Glass 技术概览](https://developer.apple.com/documentation/technologyoverviews/liquid-glass)。官方强调导航、控件的材质层与内容层分工。本项目是 Express/EJS Web 应用，不能声称使用原生 SwiftUI/UIKit 材质，也没有官方认证或逐像素一致的 iOS 27 实现。

- 玻璃用于顶部栏、侧栏、菜单、标签导航、分类分组栏和移动底栏；账务内容保持稳定对比度。
- 白天采用透光浅色、冷暖背景反射、边缘高光和较弱投影；夜间独立调整底色、透光、文字、蓝色按钮前景与边缘强度。
- Web 实现使用 backdrop-filter、渐变、高光和指针反馈；未实现原生实时折射、材质变形或系统级合成。
- 保留键盘焦点、Escape、焦点返回、减少动态/透明及高对比回退；浏览器不支持模糊时使用实色背景。

## 验证方法与结果

- `node test/run-all.js`：21/21 套件，1092 通过、0 失败。分类 59 断言覆盖共享分类副本、隔离、历史引用、删除恢复及本轮分组搜索/重定向。
- `node test/selfcheck-static.js`：15/15，60 个 JS 语法、36 个 EJS 编译通过，版本三件套一致。
- `node test/verify-ui-browser.cjs`：27 路由 × 390/820/1280/1920/2560px × 明暗主题，共 270 视图；另 25 个认证/起始状态、68 个设置标签和编辑变体。
- 页面矩阵记录横向溢出、状态码、卡片宽高与剩余空白；变体使用实际点击切换设置标签，并断言单卡宽度上限，避免只修改 URL hash 却截图旧面板。
- 浏览器交互覆盖自然高度、宽度约束、分类编辑/删除/恢复、无 JS、父类过滤、下拉 Escape 与再次打开、周期新增控件、焦点恢复、平板粗指针、200% 显示缩放及短屏详情可达。
- 图片与测量位于忽略目录 `.screenshots/audit-before/`、`.screenshots/audit-after/`、`.screenshots/qa.json`；功能测试使用独立数据库和 8099 端口，浏览器使用 `.tmp/data-ui-browser/` 与 5113，不触碰真实 `data/`。
- 独立审查发现移动侧栏定位被通用材质规则覆盖，已在手机/触屏断点恢复 fixed，并补充 390px 手机与 1024px 触屏平板的抽屉计算定位、主内容 left/width 检查，避免“没有横向溢出但内容被侧栏挤窄”的漏检。
- 修复后浏览器全量复验通过；独立审查复核确认原 P1 消除，无其他阻塞项。

验收范围是上述入口、变体和操作；不把自动化通过等同于所有真实账本内容或 Apple 原生渲染完全一致。

## 追加：全站内容自然平铺

维护者指出一级分类内部滚动不合理，要求全站统一设计。此前以固定高度维持侧栏紧凑，反而增加了嵌套滚动；本次将“内容随页面自然展开”作为统一约束，以下结果替代前文分类侧栏与明细内部滚动安排。

- 一级分类移至内容顶部，桌面自适应多列、手机两列，全部显示并自动换行；移除固定定位、限高和横向滚动，较长分类名称允许换行。
- 设置标签、记账类型、筛选标签自动换行；报表分类排行、操作审计日志、记账分类列表移除纵向限高；明细摘要/详情侧栏按内容自然增长，通过页面访问末尾操作。
- 全页扫描实际产生纵向滚动的内容节点，同时检查设置六个标签与流水编辑变体。必要的应用导航、弹出菜单、模态窗口、聊天记录保持其交互边界；窄屏财务表格保留横向滚动以维持列的对应关系。
- 浏览器新增一级分类网格/自然高度/全部链接位于容器内断言；270 默认视图与 68 变体均检查内容内部滚动。短屏长备注测试改为通过整页滚动访问详情末尾按钮。
- 独立审查确认无新增 P1/P2，并采纳审查建议将设置管理标签纳入内部滚动扫描。
- 最终验证：21/21 套件、1092 断言、静态 15 项通过；浏览器 270 视图、68 变体与 25 起始状态通过，默认页和变体均未检出内容内部纵向滚动；10 种主题/宽度组合的分类网格断言通过。
