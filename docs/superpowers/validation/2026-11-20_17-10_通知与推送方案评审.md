## 推荐架构和配置

现有业务和新增提醒均先生成站内通知。后台按当前接收人的设置读取新消息、筛选通知类型并创建渠道投递记录。设置页支持全部类型转发，也支持按类型选一个或多个渠道。每条站内通知与每个渠道最多一条投递记录。业务写入只依赖站内通知，发送队列维护和网络请求均由后台独立处理。测试按钮直接向所选渠道发送合成文案，并如实返回渠道回执。

日预算也可以加到现有预算页，复用预算配置及站内预警，但需一并决定日预算是否在预算页展示以及预警线和 100% 超支是否各提醒一次。推荐把当天预警作为一条独立通知规则，借用预算计算与筛选口径，直接使用单阈值每日一次的规则。

SQLite 追加通知类型、个人渠道、类型与渠道关联以及投递记录。投递记录兼作队列和设置页日志。消费规则另存每日预算、预警比例和范围。扫描游标和启用边界持久化，首次启用只转发此后的新消息，计划提交与游标推进在同一个事务。关闭渠道或失去对应账本权限时取消待发投递。备份恢复期间暂停派发，恢复后的历史未发任务不自动重放。缺少解密密钥时只暂停受影响渠道。

- Webhook 支持结构化地址或完整 URL，表单选择其一以确定发往何处。GET 配 Query，POST 可选 JSON 或表单，两者皆可配置允许的请求头。仅使用固定变量集合，按所在位置编码，模板只填入业务字段。请求目标由明确配置决定。
- Server 酱使用独立适配器。区分 Turbo 和 Server 酱³ 的 SendKey 与端点，允许填写自定义服务地址，按版本生成 `title/desp` 并核对业务状态。[Server 酱官方文档](https://sct.ftqq.com/docs/getting-started/sendkey/)
- Bark 支持官方和自建服务，复用 POST `/push` JSON 入口。协议、域名或 IP、端口及反向代理路径可配置。`device_key` 用于设备认证，分组、铃声、角标、级别和跳转等作为可选项。[Bark API V2](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)
- 适配器各自生成请求并解释回执，共享安全出网、超时、状态和日志。不增加大型依赖。测试用合成文案发真实请求，返回“服务已接受”或相应错误。能确认服务接受时不声称手机已收到。通用 Webhook 默认按 HTTP 成功状态判断，若服务在 2xx 响应里返回失败，可另行配置业务判定。
- 建议按本人账号管理渠道、订阅哪些通知类型和查看投递记录，站点管理员批准具体局域网目标。内网按主机或 IP 与端口授权，验证实际连接地址，控制重定向和基础设施敏感地址。住宅局域网自建服务仍可使用。默认验证 HTTPS 证书，密钥、敏感头、带凭据的 URL 路径及查询字段加密保存。专用密钥在数据库之外管理。日志只保存事件摘要、渠道、时间、状态和受限错误码，配置 API 和 SSR 均脱敏。[OWASP 服务端出网安全指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

## 触发、去重与补发口径

- **订阅续费决策提醒** 订阅里设「提前提醒（天）」为 2，12 月 5 日扣费时，通常在 12 月 3 日的首次检查生成站内通知。现有算法按窗口触发，服务错过 3 日时可在仍有效的窗口内触发。启用「订阅即将扣费」的渠道收到该消息。到期自动记账仍由原开关控制，商家取消由用户操作。
- **信用卡提醒** 新增出账日站内提醒，可在出账日当天或提前 N 天提醒，金额未确认时展示可确定的卡名、日期及还款日。在已有还款提醒上增加可选的提前天数及当天提醒，旧卡保留当前三天内一次的行为，用户可设置 7／3／1 天等档位。每个档位只生成一条站内通知，按最新还款日及待还状态判断。
- **转发内容和时效** 发送站内消息供用户阅读的标题和正文，移除内部去重标记，可附通知中心的安全访问链接。接收规则按事件类型筛选。历史存量和过期消息不补发。服务重启后在有效期内继续处理持久投递任务。阅读站内消息不改变手机投递状态。
- **当日消费预警** 按所选时区的自然日、记录上的记账日期累计。用户自行填写每日预算金额和提醒百分比，可使用全账本、分类或账户范围。每日预算 300 元、比例 80% 时，当日累计达到 240 元便生成站内通知，启用该类型的渠道同步收到。短周期读取已提交的流水，发生增改删时按当前数据重新评估。每条规则每天只产生一次通知，达到 100% 或降下后再次达到都不重发。尚未发送且已过期的当日消费通知不补发。
- **消费金额口径** 首版建议沿用现有预算的本位币支出和费用，部分代垫仅计自用分项，转账和代垫回款自然排除。退款如果改变了原消费记录，按修改后的记录重算。单独入账的退款目前与消费分开统计，建议当日预警也沿用这一口径。如果维护者希望退款冲减，需另行确认按退款日还是原消费日，以及如何可靠关联原消费。
- **重试与防重** 定时重复、并发认领、重启通过持久事件及投递唯一约束控制；故障恢复仅发送还有效且未处理的提醒，过期档位不批量追发。对可确定的临时失败有限退避，例如总计三次并遵守限流回执。已发出请求但响应超时或进程中断的情况可能已送达，记录“结果未知”，默认停止盲目重发。有接收端幂等支持时可携带稳定投递 ID。
- **隐私与免打扰** 建议首版提供隐藏金额模式，模板中的金额变量同样脱敏。免打扰是可选的第二步。在投递模型保留延后时间，启用后延后至安静时段结束，重查已付、取消或改期；必要时只保留一条仍有效的到期／逾期提醒，不扫过期历史。
