# 代垫复用普通账单编辑

## 目标

维护者决定替换独立的双列代垫编辑页面。账单明细的代垫付款行使用普通编辑、删除图标；共用编辑页左侧处理付款信息，右侧在分类下直接登记和管理回款。

## 决策和执行

1. 核对项目交接本、UI 和金融约定、当前分支及历史方案。以 `48a9198` 为本轮基线，保留三份既有未跟踪归档。
2. 把代垫编辑接入 `src/routes/transactions.js` 的既有编辑路由及 `src/views/txn-form.ejs`。代垫专属字段仍调用 `src/lib/advances.js` 现有服务，沿用分类、自用金额、禁改条件及操作键。旧编辑链接重定向到共用页。
3. 把登记及回款历史提取到 `src/views/partials/advance-recovery.ejs`，与代垫详情共用。显式指定 HTML 表单所有者，使编辑与回款分别提交。回款操作完成后返回发起入口，撤销或恢复也适用。普通账单明细的返回保留筛选。
4. 主付款行删除调用现有整笔撤销服务。有效回款、原支出恢复、信用卡关联保护沿用同一事务路径，付款副分项继续拒绝单删。开放 API 及两份技能契约保持原状。
5. 更新 `test/ui-advance-checks.cjs`，验证真实分类选择、两表单隔离、明细标准按钮、已收齐后编辑、回款失败回填和整笔删除。另运行两版 Node 全量、静态检查、全站浏览器和独立审查。
6. 补齐共用编辑页的「清除分类」，与原生未分类选项同步，保留旧代垫编辑可清空自用分类的能力。类型切换导致分类清除时同步提示和按钮，操作清除后焦点回到分类搜索。
