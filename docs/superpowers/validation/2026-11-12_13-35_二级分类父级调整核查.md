# 二级分类父级调整核查与修复

创建：2026-11-12 13:35（Asia/Shanghai）。状态：核查后维护者明确要求“修复它”，修复、验证、独立审查及main合并均完成；持续更新同一文档。

## 目标与要求

维护者最初反馈已有二级分类似乎不能修改其所属一级分类，要求核实是否存在问题；核查确认后追加“修复它”。核查阶段只复现和登记，修复阶段按下文最小方案实施。不修改用户真实分类或账目，不将尚未完成的门禁声称为通过。

## 决策理由与执行步骤

1. 阅读BOARD、文档导航、协作与UI分类约定，核查分类编辑模板、公共分类服务、开放API和现有测试/技能。
2. `src/views/partials/category-entry.ejs`的编辑表单只有name/icon/color，无parent_id；`src/views/categories.ejs`仅新建表单有“所属一级分类”。因此已有二级分类没有调整父级的UI入口。
3. `src/lib/categories.js`中create接受parent_id并检查有效一级/同收支类型；update只更新name/icon/color，忽略body.parent_id。`src/routes/accounts.js:237`的网页更新与`src/routes/openapi.js:841`的开放API均调用同一update，因此均不支持调整父级。
4. 使用一次性隔离目录`.tmp/data-category-parent-probe-20261112-1335`初始化测试库，创建两个自定义一级分类和一个二级分类，再向update提交新父级。未触碰`data/homeledger.db`、5111或5112账本。
5. 现有分类回归覆盖新建父级、复制映射、删除恢复等，没有覆盖已有二级分类换父级。两份技能目前声明编辑名称/图标/颜色，没有声称支持换父级；这是未实现的能力，不是本轮布局改动已经实现却忘记同步的接口。
6. 只新增本归档及BOARD待办。没有进行产品修复，没有运行无关全量回归，没有启动8099/5113测试实例。

## 关键数据与结果

隔离复现返回：

```json
{"before_parent":210,"requested_parent":211,"after_parent":210,"returned_success":true,"parent_unchanged":true}
```

结论：问题确实存在。创建二级分类时可指定父级，编辑已有二级分类时不能修改；直接传parent_id也会被忽略但返回成功。
