# 补全代垫账单编辑

## 目标与范围

维护者指出上一轮代垫编辑缺少分类及其他常用字段。本轮继续当前模型，沿用 `codex/advance-edit-navigation` 与 `3262afd`，保留另外三份未跟踪归档。

## 决策与产出

- 「编辑代垫」显示同一份完整表单，补自用支出分类、归属人、标签、预测标记、金额、账户、日期、时刻、自用类型。分类只记录在自用消费分项，纯代垫仍无消费分类。
- 同一公共服务按改动内容保存。分类和一般详情即使已收齐仍可原位更改。发生资金字段变化时调用已有整体更正，保留未回款限制、确认信用卡账单保护、原始来源约束和幂等重试。已在原主单的凭证沿用到新主单。
- Web 表单和 `POST /advances/:id/details` 同源，原 `/amend` 保持可用。错误回填包含新增字段，Agent 技能与参考文档主副本同步。
- 验收重点为浏览器实际保存分类和标签、已有回款本金不变、账户日期等可整体更正及幂等、防止误设收入或跨账本分类、已归档原分类和来源凭证保留。

## 验证与发布状态

- 最终 Windows Node 24 和 Node 22 UTC 全量各 32 套，1725 项通过。前两次新增接口断言失败分别因数字布尔标记和 Unicode 标签排序假设，修正后通过。日志 `.tmp/advance-full-edit-win24-final.log` 和 `.tmp/advance-full-edit-win22-utc-final.log`。
- 隔离 Edge 聚焦 8 组通过，涵盖明暗、390/1920、启用及禁用 JavaScript。实际在收齐后改分类、归属人和标签，测试读取原交易确认保存。未回款时从同一表单更正金额和日期，既有回款、凑整和导航旅程通过。实际查看深色手机表单。日志 `.tmp/advance-full-edit-browser-final.log`。
- 静态检查 15 项通过。技能主副本一致，差异格式检查通过。独立复审无 P1/P2，审查覆盖归档分类、来源凭证、幂等和已有回款约束。
- 最终拒绝 `personal_cents:null`，避免空值解释成零。资金字段锁定时使用数据库值，防止并发回款使表单把旧草稿的值当成只读事实。分类置于表单最前面。
