## 5. 不能退回的当前设计

### UI/UX

- Apple风格是视觉方向，**没有“完全按照iOS27官方规范/官方认证”的验证结论**。Web CSS玻璃不等于原生实时折射。明暗主题分别验收，账务内容优先可读、稳定。
- 首页按独立信息列适应宽屏，内容自然高度，不用等高卡片制造大洞，也不把手机卡片横向拉满来冒充适配。
- 一级分类完整平铺，二级按当前组选择；普通内容不设内部纵向限高滚动。表格必要横向滚动、菜单/弹窗/聊天滚动有自身边界，不能批量清除所有overflow。
- 账户按类型形成全宽独立段，段内卡片自适应平铺，不让某类账户数量撑高相邻类型；段头数量与分币种余额，编辑展开占本组整行。
- 常规操作统一btn系列，不能同类有的按钮有的裸字+箭头。表单/控件继承字体；明细/子详情有明确父级返回，不依赖history.back。
- 记一笔类型/还款对象就地切换，宽度位置稳定，适用的日期/金额/账户/时刻/模式和各自草稿保留；切换不能把清空时刻当“没值所以忽略”。
- 分类/记账/设置/编辑/归档等受公共CSS影响的页面一起复核。用户反复强调“主动全站查，不等我逐处指出”。

### 分类与Emoji

- `is_system`仅来源标记，不代表只读。系统/自建分类可修改、软删除/恢复。
- 当前账本修改共享模板要走 `src/lib/categories.js`，事务生成副本并保留流水、预算、计划、习惯等引用；不能改坏其他账本模板。
- 二级只能移动到同账本、同收支类型、有效一级，保留分类身份；删除父级隐藏子树，恢复不覆盖子项自身删除状态。
- 一级排序；二级在所属一级内排序，完整ID集合和expected_ids防旧页面覆盖，同顺序重试成功。记一笔和分类选择共用顺序，金额报表排行不跟着变。
- 数百个Emoji按场景/中文同义词检索，新建与编辑共用组件，仍可自定义输入。Emoji外观由设备字体决定，不是引入另一套固定图标图片库。

### 资金流与消费口径

- 总览两区同屏；报表默认资金流，可切消费，两种口径不要相加。
- 旧summary API缺省仍保持消费口径；新调用显式传`basis=cashflow`查询资金流，不能用网页默认值推断API默认值。
- 资金流：现金/储蓄卡/支付账户/预付等实际资金账户净变化；自有资金互转抵销，实际借出/还本金影响资金流。
- 消费：自用消费、利息费用等；借钱/贷款/信用卡还款本金、代垫本金不再算消费。信用卡刷卡消费保留，后来还款不重复计消费。
- 净资产、总资产、负债用醒目摘要，不降回顶部一行小字。
- 普通支出可用信用卡；排除loan/receivable/payable。普通转账两端排除credit/loan/receivable/payable；真实还款用统一金融入口。`account-policy.js`决定资格，不从名称猜类型。

### 借钱、贷款、卡和定期账单

- `/debts`是亲友“借钱台账”，稳定条目ID，不按姓名合并；期初登记不凭空造现金流，借出/借入/收还本金无分类。
- `/finance`管理贷款/车贷等合同、计划、信用卡账单和实际还款。金融到期只提醒，不自动代记真实银行付款。
- 信用卡按账户+账期自动归集消费/退款/还款，可按银行实际账单校正。普通还款默认自动抵最早到期的已出账账单，多付留预还款后续自动抵；手工分配是例外，不逼普通用户逐期指定。
- 贷款正常还款带最近未还期本金/利息/费用；实付与计划不符不能猜利息。
- 银行特殊手工计划仅在选择该方式时展示，属于高级例外，不作为普通登记必填；正常流程保持简单。
- `/recurring`用于工资、房租等固定收支；`/subscriptions`管会员续费；金融计划单独管理。模块保留，各司其职，不因为都“周期”就一删了之。
- 周期执行用(rule_id,scheduled_date)幂等运行记录；付款用operation_key。已有资金来源通过公共服务关联，禁止普通转账/支出再记一份。
- 已确认卡账单、活动分期、占用来源、手工分配有保护；不能绕保护改原流水。信用卡一组拆分写齐后再统一刷新，不能在临时40元状态把原100元账单的80元手工还款误判超额。

### 时间（注意方案已演进）

- `txn_date`发生日，`txn_time`可空实际时刻，`created_at`系统录入审计。禁止把旧未知时刻回填为录入钟点。
- 最新网页即时手动新建：auto模式只对当天，在成功保存时取实例当前时刻；explicit按填写值；unknown明确留空。补记其他日auto不伪造时刻，编辑省略/清空按当前接口契约执行。
- API、AI、导入缺少时刻仍未知；用户明确“现在/刚发生”才可读取/ping按实例时区取实际时间，并在重试复用。AI不得无依据造12点等钟点。
- 发生日排序：日期优先，同日实际时刻；未知只以created_at钟点作排序参考，再用created_at/id稳定排序。**“未知固定靠后”是已被替代的旧方案。**
- `created_desc/created_asc`是独立录入时间排序；网页按录入日分组，同时标真实交易日；recent API按最近录入，刚补记旧账也能找到。
- 金融已有来源时刻由来源主导，auto模式不能拿本次录入时刻覆盖；规范化时刻参与幂等签名，同key重试不漂移。

## 6. 部分代垫与凑整：最新核心账务

### 原付款

付款100=自用消费40+帮同事代垫60。真实分项为expense40和资金账户→受控应收账户transfer60，合计只扣100；消费/预算从付款当天只计40，应收60，信用卡原账单仍是100。全额代垫自用0时没有虚构零额消费。

先收20再收40：两笔资金流入冲减应收，不是消费口径收入。跨月也不把本金回收算下月收入。`splits`只是分摊备注，**没有完整多人AA结算能力**；旧整笔reimburse也不能替代部分代垫回收。

已有普通支出可以明确确认后转换，原记录软停用、保留来源/附件/追溯，不能再次扣款；更正、撤销、恢复必须整体操作。订阅、周期、已报销/分摊、金融占用/分期/确认卡账单等不支持的来源不可强行转换。

### 朋友凑整多给

用户已明确选择：**输入实收20，18.99回本，1.01计其他收入**，不做待退负债模式。

操作：账单明细→代垫与回收→详情与回收→实际到账金额填20→勾选“朋友凑整，多出的计入收入”→确认收回。

| 项目 | 结果 |
|---|---:|
| 收款资金账户增加 / 资金流入 | 20.00 |
| 应收本金减少 | 18.99 |
| 凑整差额收入 | 1.01 |
| 本次新增消费 | 0.00 |
| 剩余待收 | 0.00 |

- 未明确确认的超额请求拒绝，旧客户端不会静默把多收当收益。误转需退款不能假选该选项。
- `amount_cents`为回款实收；`principal_cents`为本金；`excess_cents`为差额；`transaction_id`关联本金转账，`excess_transaction_id`关联income。全部整数分、同事务。
- `received_cents`保持累计回本；另有`actual_received_cents`和`excess_received_cents`，待收仅扣本金。
- `collect`新增`excess_handling:'income'`、可选有效`excess_category_id`；默认找当前账本有效“其他收入”，否则未分类，不复活分类。
- 多次10+10回18.99时，后一次回本8.99、差额1.01；已结清后不借此入口追加纯收入。
- 整体撤销/恢复两份分项；恢复容量检查本金，不能拿实收20与本金18.99比较。分项不能从普通编辑/删除/恢复/报销/批量操作/金融来源绕过。
- 一次实际到账在资金流只计一笔；默认账单显示20，收入筛选可看1.01，账户明细保留18.99和1.01。默认搜索/金额筛选、日收入小计不能漏隐藏差额。
- CSV按真实资金分项导出，不能只导合并列表而漏1.01。CSV原始分项不是重新构造完整业务关联的承诺；完整数据库备份与扁平表格不要混淆。
- 旧回款迁移为本金=原金额、差额0，初始化及备份重开可重入。
- 目前本位币、同币种、每付款一个对方，可多次回款；待退款、少收减免、跨对象预存、完整多人AA不在本次完成范围。

### 本地与远端SHA不同的原因

本地SSH缺可用密钥，历史上通过已连接GitHub工具发布精确blob/tree，远端提交以远端main为父，本地保留过程历史。因此SHA不同但文件树相同；本地旧origin/main引用也未自动刷新，`ahead`不代表没上传。

Git网络操作仍要求SSH，不执行HTTPS git绕过；有连接器可按既有授权保留远端父提交发布。不要强推、reset已发布main或为消除ahead重写历史，也不要直接假定git pull能快进。遇到自动审批/额度阻断如实说明，不绕过审批；此前最终文档同步曾因此中断，用户继续后正常重试已同步成功。
